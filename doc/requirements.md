# 外送系統 需求規格書 (Requirements Specification Document)

- **文件版本**：v1.0.0
- **建立日期**：2026-07-16
- **撰寫人**：AI 需求訪談小助手 (requirements-interviewer)

---

## 1. 專案背景與目標 (Project Background & Objectives)
- **背景**：建立一個三方媒合平台，解決大眾日常用餐不便，協助在地店家拓展客群，並為外送員提供靈活的就業與工作機會。
- **目標**：以最簡可行產品 (MVP) 的形式，於單日之內完成設計、開發、與測試，並部署至線上環境。

## 2. 目標受眾與使用者畫像 (Target Audience & Personas)
- **一般消費者 (Consumer)**：希望瀏覽附近店家菜單、快速點餐且以現金貨到付款的消費者。
- **合作店家 (Merchant)**：希望拓展線上接單管道，並自行管理菜單的在地餐廳。
- **外送員 (Rider)**：尋求配送訂單、賺取外送費並協助配送餐點的自由工作者。

## 3. 功能需求範圍 (Functional Requirements & Scope)

### 3.1 核心功能 (In Scope)
- **消費者端 (Consumer)**
  - 帳號註冊與登入（電子信箱 + 密碼）。
  - 瀏覽合作商家列表。
  - 查看商家菜單、將商品加入購物車。
  - 填寫送餐地址，提交訂單（僅支援貨到付款 COD 模式，固定加收外送費 39 元，無起送價限制）。
  - 訂單狀態追蹤（等待接單 ➡️ 商家製作中 ➡️ 外送員配送中 ➡️ 已送達）。
- **商家端 (Merchant)**
  - 商家註冊與登入。
  - 菜單與商品管理（新增商品、修改名稱/價格、刪除商品）。
  - 接收消費者訂單、確認接單並開始製作。
  - 製作完成時點擊「餐點已完成，等待外送員取餐」。
- **外送員端 (Rider)**
  - 外送員註冊與登入。
  - 訂單大廳：瀏覽目前待接單的訂單。
  - 點擊接單（不支援拒絕已指派/接下的訂單）。
  - 更新訂單進度：已取餐（開始配送） ➡️ 已送達（手動收取現金並結案）。
- **平台派單系統 (Dispatch Engine)**
  - 支援自動/手動指派訂單給外送員的基礎系統機制。

### 3.2 排除範圍 (Out of Scope)
- 不支援任何線上金流支付（僅支援現金貨到付款 COD）。
- 不支援平台內部即時聊天（即時通訊功能）。
- 外送員不支援「拒絕接單」（必須接受或由大廳領取，接單後不能退單）。
- 不包含外送員的實體 GPS 地圖定位追蹤（進度由外送員在系統手動按鈕更新狀態）。
- 不支援消費者或商家於下單後手動取消訂單（一旦下單即無法於前端取消，需聯絡管理員或按狀態流轉結案）。

## 4. 技術架構與限制條件 (Technical Architecture & Constraints)
- **開發技術棧**：前端 React + 後端 FastAPI，本地資料庫使用 SQLite，生產環境使用 Render.com 與 Render PostgreSQL。
- **第三方整合**：無其他外部整合需求（無簡訊驗證、無地圖 API、無線上支付）。
- **系統限制**：確保本地開發環境與 Render.com 正式環境均能順利運行。

## 5. 使用者流程與 UX 規劃 (User Flows & UX Design)
- **核心使用者路徑 (Critical User Journey)**：
  - 消費者下單 ➡️ 商家接單製作並完成 ➡️ 外送員接單、取餐並配送 ➡️ 外送員收取現金並送達結案。
- **介面/體驗要求**：現代簡潔風格，以食慾感強烈的「亮橙/橘色」為主色調。使用卡片式佈局，確保在行動裝置網頁（Mobile Web）有絕佳的 RWD 操控體驗。

## 6. 專案時程與成功驗證標準 (Project Schedule & Success Criteria)
- **預估開發時程**：預計於 2026-07-16 當天完成開發與測試。
- **驗證指標 (Success Criteria / 里程碑)**：
  - **核心里程碑**：各角色功能可完整、順暢地跑完一次端到端（End-to-End）訂餐流程。
  - 系統響應：頁面載入速度在行動網頁下小於 3 秒。
