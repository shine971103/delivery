## 3. 技術選型與決策 (Technical Decisions)
- **後端 FastAPI**：
  - 決策理由：具備極高運行效能、支援非同步 (asyncio) 運作，且能自動產出 OpenAPI (Swagger) 互動式 API 文件，加速前端串接。
- **前端 React.js**：
  - 決策理由：组件化開發利於維護，搭配 RWD（響應式設計）能快速滿足手機瀏覽器與桌機瀏覽器的跨平台操作，無須第一階段打包 App。
- **本地 SQLite 與正式 PostgreSQL**：
  - 決策理由：SQLite 作為本地開發，完全零設定且速度極快；生產環境切換為 PostgreSQL，以利多執行緒與雲端託管安全性。
- **Render.com 部署**：
  - 決策理由：提供簡便的 Web 託管與資料庫雲端部署，且能自動與 GitHub 連動進行自動化 CI/CD。

## 4. 已確認的業務規則 (Confirmed Business Rules)
- **外送費與起送金額**：
  - 每筆訂單不論距離或商家，一律加收 **固定 39 元外送費**。
  - **無起送價**限制（消費者點選任何金額皆可提交訂單）。
- **付款方式**：
  - 僅支援 **貨到付款 (COD)**。外送員送達時，應口頭向消費者收取該訂單之總金額（餐點價格總計 + 外送費 39 元）並交付餐點。
- **搶單衝突解決機制**：
  - 當多名外送員於大廳同時搶接同一筆 `ready` 訂單時，系統採用資料庫鎖機制，限制僅首位成功寫入外送員 ID（綁定 `rider_id`）者得單，其餘外送員之請求一律回傳 `409 Conflict` (接單失敗)。
- **取消訂單規則**：
  - 系統**不提供訂單取消功能**。消費者送出訂單後，必須依照流程流轉（等待接單 ➡️ 製作中 ➡️ 配送中 ➡️ 送達結案）。

## 5. 架構與防護限制 (Architectural Constraints)
- **環境變數分離**：禁止將任何 API 金鑰或密碼寫入代碼或 Git。敏感金鑰統一放置於 `.env`，正式部署設定於 Render.com 儀表板。
- **軟刪除限制**：使用者、商家、商品若需移除，應使用 `deleted_at` 進行軟刪除，以防止破壞歷史訂單資料庫的外鍵完整性。
- **Render 免費方案冷啟動**：Render.com 免費主機會在無流量一段時間後自動休眠。首次點擊可能會有約 30 秒至 50 秒的冷啟動延遲，前端頁面需有載入中 (Loading) 提示以維護良好 UX。
